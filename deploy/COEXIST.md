# Соседство LiveKit с уже существующим приложением

Короткий ответ: **машину — да, процесс и порты 80/443 — нет.** LiveKit не встраивается внутрь другого приложения. Он садится рядом отдельным сервисом.

## Что можно переиспользовать

| Уже есть на сервере | Переиспользуем? | Как |
|---|---|---|
| VPS / VM | да | второй compose / systemd unit |
| nginx / Caddy / Traefik | да | новый `server_name`, старый vhost не трогаем |
| Docker | да | этот `deploy/docker-compose.yml` рядом |
| Домен | да | поддомены `call.` и `livekit.` |
| Пользователи существующего приложения | позже | token API проверяет их сессию и выдаёт LiveKit JWT |
| Порты 80 и 443 | нет, они уже заняты приложением | LiveKit слушает 7880/7881/7882/3478 |
| UDP медиа-диапазон | только если свободен | здесь mux на **одном** UDP 7882, не 50000–60000 |

## Чего нельзя

- Проксировать WebRTC UDP через nginx. Signaling (WSS) — да, медиа — нет: UDP 7882 и TURN 3478 должны доходить до хоста.
- Поставить официальный LiveKit installer с Caddy на 80/443 — он отберёт порты у текущего приложения.
- Ждать, что одно ядро и 512 МБ потянут и тяжёлое приложение, и много одновременных звонков. Для пары 1:1 каналов обычно хватает; смотреть RAM/CPU и исходящий трафик.

## Порты, которые должны быть свободны

```
TCP 7880   signaling (можно только localhost, снаружи — через nginx)
TCP 7881   ICE/TCP fallback, снаружи
UDP 7882   медиа (mux)
UDP 3478   встроенный TURN
TCP 3080   UI + token API (можно только localhost)
```

Проверка на сервере:

```bash
ss -lntu | grep -E '7880|7881|7882|3478|3080'
```

Если 3478 занят (редко), смените `turn.udp_port` в `livekit.yaml`. Если 7880 занят — смените `port` и nginx upstream.

## Как поставить рядом

1. Скопировать `deploy/` на сервер (или клонировать репо).
2. `cp deploy/.env.example deploy/.env` и заменить секрет: `openssl rand -hex 32`.
3. В `.env` выставить `LIVEKIT_URL=wss://livekit.example.com`.
4. DNS: `call.example.com` и `livekit.example.com` → IP сервера.
5. Добавить vhost'ы из `nginx.example.conf` **рядом** с существующим, не вместо.
6. Открыть в firewall UDP 7882 и 3478, TCP 7881 (и 80/443 если сертификаты через nginx).
7. `cd deploy && docker compose up -d --build`

Существующее приложение при этом не переезжает и не переслушивает порты.

## Если Docker уже есть у текущего приложения

Два варианта:

- **Отдельный compose** (предпочтительно) — этот файл, общая сеть не обязательна.
- **Вписать сервисы `livekit` и `app` в существующий compose** — только если уверены, что имена сервисов и порты не пересекутся.

`network_mode: host` в LiveKit-доках даёт лучший UDP, но на общем сервере опаснее (все порты из yaml садятся прямо на хост). Этот compose публикует только нужные порты.

## Чего не хватает, чтобы ответить «точно да» про ваш сервер

С этой среды сервер не виден. Нужно знать:

1. Что уже слушает 80/443 (nginx / Caddy / само приложение).
2. Есть ли Docker.
3. Свободны ли UDP 7882 и 3478.
4. Есть ли домен, на который можно повесить два поддомена.
5. Сколько RAM свободно (ориентир: +300–500 МБ простоя, плюс трафик на звонок).

Без этого деплой на VPS лучше не запускать вслепую. Локально стек поднимается скриптом `scripts/dev.sh`.
